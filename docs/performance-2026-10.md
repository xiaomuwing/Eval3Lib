## 1. 结论摘要

- **数值快路径**（整树单 lambda）：常量 **1.0 ns**、变量 **4.8 ns**、`Round` **5.9 ns**、`Sum` **3.1 ns**，全部 **0 B/次**。
- **对象路径**（文本模板）：**66.0 ns / 168 B**（旧路径 104.0 ns / 400 B），分配减少 **58%**。
- **24 线程并行**：`Round` 公式 **1.18 B 次/秒**（旧路径 553 M 次/秒，2.1×）。
- **首次解析**仍是 **699 ns / 1 648 B**（AST 节点主导）；**同一公式重复解析** 走 AST 缓存，**21 ns / 0 B**。
- 所有数字均为**同进程 A/B**：`legacy` = 关闭整树编译的旧路径，`new` = 当前默认路径。

## 4. 口径与注意事项

1. **`legacy` 路径**：`EvaluatorOptions.UseWholeTreeNumericCompiler = false`，保留改造前的逐节点委托 / 树遍历行为。
2. **首次解析**数据使用 `EnableParseCache = false` 的独立 Evaluator，避免 AST 缓存掩盖解析成本。
3. 绝对值随 CPU 频率 / 功耗状态漂移，**同一次运行内的比值**才是稳定指标；工具每项预热 300 ms、取 3 轮最优。
4. `Evaluate()` 的 0 B 是基准中"结果未被使用"时 JIT 逃逸分析消除了根节点装箱；真实消费者为**根节点一次装箱（24 B）**。
5. `DataTable.Compute` 使用无 `%` 的等价公式（它不支持 double/int 混合取模），仅作数量级参照。
